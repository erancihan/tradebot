# Program Design: portfolio companion

Written per epic, right before that epic's slices start. Approved by owner
delegation when written.

## E1: housekeeping

### Files
- `tests/test_code_shape.py` (new). Walks `tradebot/` and `tests/` with
  `ast`. Fails when a function or method body spans more than 60 lines.
  Fails when a module under `tradebot/` spans more than 200 lines. Prints
  the offenders with path and line. Tests modules have no module limit.
- `tradebot/cli/__init__.py` (new). `build_parser()` and `main()`. Each
  command group registers its own subparser through a `register(sub)`
  function, so the parser builder stays short.
- `tradebot/cli/common.py`: logging setup, summary printers, shared helpers.
- `tradebot/cli/demo.py`, `backtest.py`, `run.py`, `status.py`,
  `universe.py`, `data.py`: one module per top-level command.
- `tradebot/cli/arena.py`: `list`, `run`, `validate`, `history`, `show`.
- `tradebot/cli/arena_gate.py`: `gate` and its report helpers.
- `tradebot/cli/arena_journal.py`: `journal`.
- `tradebot/cli/arena_league.py`: `league`.
- `tradebot/cli/season.py`: `season {create,seed,list,standings,run}`.
- `pyproject.toml`: script entry stays `tradebot = "tradebot.cli:main"`.
- Modules flagged by the shape test are split along their existing section
  comments, one concern per file, package re-exports kept so imports in
  tests and `algos/` do not change:
  - `tradebot/arena/season.py` to `season/` package: `model.py` (config,
    store access), `feeds.py` (replay, Alpaca, stream feeds), `daemon.py`
    (market-hours loop).
  - `tradebot/arena/gate.py` to `gate/` package: `criteria.py`,
    `report.py`, `evaluate.py`.
  - `tradebot/arena/store.py`: `store.py` (runs) and `journal.py`.
  - `tradebot/consortium.py`: `consortium/` package: `voice.py`,
    `blend.py`, `panel.py`.
  - `tradebot/backtest.py`: `backtest/` package: `result.py`, `marks.py`,
    `runner.py`.
  - `tradebot/arena/runner.py`: `runner.py` and `isolation.py`.
  - `tradebot/selection.py`: `selection/` package: `base.py`, `ranked.py`,
    `regime.py`.
  - `tradebot/engine.py`: `engine.py` and `engine_pass.py` (the per-pass
    gather and submit steps), later folded into `advisor.py` in E3.
  - Web: `repository.py` into `repository/` (trading, arena, season),
    `jobs_service.py` into `jobs/` (registry, backtest, dryrun, frames),
    `schemas.py` and `routes/api.py` by page.
  - Data: `cache.py` into `cache.py` and `coverage.py`. `synthetic.py` into
    `synthetic.py` and `factor_panel.py`. `storage.py` into `storage/`
    (connection and schema, orders, bars, weights).
  - `universe.py` into `universe/` (screen, alpaca).
  - `broker/dryrun.py` into `dryrun.py` and `brackets.py`.
- Long functions are split into named steps: `cli build_parser` (per
  group), `gate.evaluate_gate` (one function per criterion plus an
  aggregator), `simulation.simulate` and `Backtester.run` (shared step
  helpers, lockstep test stays green), `engine.rebalance` (gather, gate,
  size, submit), `synthetic_factor_panel`, `consortium_service.panel`,
  `walk_forward`.
- Docs: `CLAUDE.md` rewritten to a map plus invariants plus gotchas, under
  300 lines. The research record and the audit history move to
  `docs/research-record.md` as a paper trail. `docs/PLAN.md` and
  `docs/DESIGN-HANDOFF.md` are deleted. `README.md` describes the companion
  flows first and the research tooling second.
- Mobile shell: `templates/base.html` gets a bottom tab bar component
  (`components/tabbar.html`) shown under `md`, the top nav stays above `md`.
  `tradebot/web/static/manifest.webmanifest` is served from a route in
  `routes/pages.py`. Icons are two PNG files generated by a script in
  `frontend/`, committed under `tradebot/web/static-src/` (not gitignored).

### Types and signatures
```python
# tests/test_code_shape.py
MAX_FUNCTION_LINES = 60
MAX_MODULE_LINES = 200
def iter_python_files(root: Path) -> Iterator[Path]: ...
def long_functions(path: Path, limit: int) -> list[str]: ...
def test_no_function_exceeds_limit() -> None: ...
def test_no_package_module_exceeds_limit() -> None: ...

# tradebot/cli/__init__.py
def build_parser() -> argparse.ArgumentParser: ...
def main(argv: list[str] | None = None) -> int: ...
# every tradebot/cli/<group>.py
def register(sub: argparse._SubParsersAction) -> None: ...
```

### Call stack
`tradebot.cli.main` -> `build_parser` -> `<group>.register(sub)` sets
`func=cmd_*` -> `args.func(args)` -> existing command bodies, unchanged.

### Test plan
- `test_no_function_exceeds_limit`: fails if any function body is over 60 lines.
- `test_no_package_module_exceeds_limit`: fails if any `tradebot/` module is over 200 lines.
- Existing CLI tests keep passing with `tradebot.cli.main` unchanged.
- `test_web.py` gains `test_manifest_is_served` and `test_tabbar_renders_on_every_page`.

### Least confident decisions
1. Module limit 200 for the package only. Tests are exempt from the module
   limit because splitting test files adds no value.
2. Splitting `backtest.py` and `simulation.simulate` risks the lockstep
   invariant. The shared step helpers must be used by both loops.
3. PWA without a service worker: pinning and full-screen work, offline does
   not. Offline is not a goal for a live trading view.

## E2: What-if simulator

### Files
- `tradebot/whatif.py` (new, core). Plan and result types plus `run_whatif`.
  If it passes 200 lines it becomes `whatif/` with `plan.py`, `run.py`,
  `compare.py`.
- `tradebot/backtest/runner.py`. `Backtester.run` gains an optional
  `cash_flows` argument: a mapping from bar timestamp to a cash amount added
  to the book before that bar is sized. Default none, so the arena loop and
  every existing test are unchanged.
- `tradebot/backtest/result.py`. `BacktestResult` records
  `total_contributed` and exposes `money_gain` (final value minus every cash
  put in) next to the existing time-weighted metrics.
- `tradebot/web/services/jobs/whatif.py` (new). Job kind `whatif`: resolves
  frames for every symbol from `BarCache` (cache only in this epic, with the
  pull hint on a miss), builds the plan, runs it, returns summary, both
  curves and provenance.
- `tradebot/web/services/whatif_presets.py` (new). Named presets, for
  example "Three index ETFs, 200 a month since 2021".
- `tradebot/web/routes/api/whatif.py` (new). `POST /api/whatif`, `GET
  /api/whatif/presets`.
- `tradebot/web/routes/pages.py`. `GET /whatif`.
- `tradebot/web/templates/pages/whatif.html` (new). Form, result card, chart.
- `frontend/src/components/whatif.ts` (new). Form state, submit, poll,
  render the two curves with the existing equity chart helpers.
- `tests/test_whatif.py` (new), `tests/test_web_whatif.py` (new).

### Types and signatures
```python
@dataclass(frozen=True)
class WhatIfPlan:
    symbols: list[str]
    start: str                      # ISO date
    end: str | None
    initial_cash: float
    monthly_contribution: float = 0.0
    strategy: str = "buy_and_hold"
    strategy_params: dict = field(default_factory=dict)
    allocation: str = "equal"
    allocation_params: dict = field(default_factory=dict)
    selector: str | None = None
    selector_params: dict = field(default_factory=dict)

@dataclass(frozen=True)
class WhatIfResult:
    plan: BacktestResult
    benchmark: BacktestResult        # equal-weight buy and hold, same cash flows
    contributions: float             # total cash put in
    comparison: dict[str, float]     # final_value, benchmark_final, gain, benchmark_gain, cagr, max_drawdown, vs_benchmark_pct

def monthly_cash_flows(index: pd.DatetimeIndex, amount: float) -> dict[pd.Timestamp, float]: ...
def run_whatif(plan: WhatIfPlan, frames: dict[str, pd.DataFrame], *, commission: float = 0.0, slippage_bps: float = 1.0) -> WhatIfResult: ...
```

### Call stack
`POST /api/whatif` -> `JobRegistry.submit("whatif", params)` -> `jobs/whatif.run_job` -> `frames.resolve_many(symbols, start, end)` -> `whatif.run_whatif` -> `Backtester.run(frames, cash_flows=...)` twice (plan, benchmark) -> `WhatIfResult` -> job payload `{summary, equity, benchmark_equity, provenance}` -> page polls `/api/jobs/{id}`.

### Test plan
- `test_monthly_cash_flows_lands_on_first_bar_of_each_month`.
- `test_contributions_raise_final_value_by_the_cash_put_in_when_prices_are_flat`.
- `test_money_gain_excludes_contributions`.
- `test_benchmark_is_equal_weight_buy_and_hold_with_the_same_cash_flows`.
- `test_run_whatif_with_a_strategy_plan_matches_backtester_directly` (lockstep).
- `test_backtester_without_cash_flows_is_unchanged` (same equity as before the argument existed, on the demo data).
- Web: `test_whatif_job_runs_from_the_cache_and_carries_provenance`, `test_whatif_uncached_range_returns_pull_hint`, `test_whatif_page_renders_presets`.

### Least confident decisions
1. Contributions are added at the first bar of each calendar month at that
   bar's open. Mid-month start dates get no partial first contribution.
2. Benchmark is equal-weight buy and hold over the same symbols. A
   single-index benchmark (SPY) is a later option, not in this epic.
3. Time-weighted metrics (CAGR, Sharpe, drawdown) stay as they are and are
   labelled "plan performance". Money gain is the headline number on the
   phone because it answers the owner's question directly.

## E3: Suggestions

### Files
- `tradebot/advisor.py` (new, core). `ProposalLine`, `Proposal`, `propose`.
  Pure: no broker call, no storage write. It reuses the engine step helpers
  in `engine/signals.py` so the engine and the advisor share one code path.
- `tradebot/engine/core.py`. `rebalance` builds the `Proposal` through
  `advisor.propose` and then submits its lines. The lockstep test asserts
  the submitted deltas equal the proposal lines for the same inputs.
- `tradebot/storage/proposals.py` (new mixin). Table `proposals`, methods
  `record_proposal(proposal, mode)`, `latest_proposal(mode)`,
  `pending_lines(mode)`, `set_line_status(ids, status)`.
- `tradebot/web/services/advisor_service.py` (new). Builds the inputs for a
  proposal from the server configuration: frames from `BarCache` (fetcher
  attached only when `AlpacaCredentials.from_env()` is present), account
  state from the paper broker when credentials exist, else from the SQLite
  log (latest equity snapshot plus positions derived from the order log).
- `tradebot/web/services/jobs/proposal.py` (new). Job kind `proposal`.
- `tradebot/web/routes/api/proposal.py` (new). `GET /api/proposal`, `POST
  /api/proposal/refresh`.
- `tradebot/web/routes/pages.py`. `GET /today`.
- `tradebot/web/templates/pages/today.html` (new) and
  `components/proposal_list.html` (new partial).
- `frontend/src/components/today.ts` (new). Refresh button, poll, render.
- `tradebot/web/app.py`. The factory takes `settings_path`; the server loads
  `config.yaml` when present, else defaults. `tradebot-web --config`.
- `tests/test_advisor.py`, `tests/test_web_today.py` (new).

### Types and signatures
```python
@dataclass(frozen=True)
class ProposalLine:
    symbol: str
    action: str            # "buy" | "sell" | "hold"
    target: int            # -1, 0, +1 after selector gating
    current_qty: float
    desired_qty: float
    order_qty: float       # signed delta, 0 for hold
    price: float
    notional: float        # abs(order_qty) * price
    weight: float | None   # post-overlay target weight when an allocator exists
    reason: str            # one sentence

@dataclass(frozen=True)
class Proposal:
    created_at: datetime
    equity: float
    cash: float
    lines: list[ProposalLine]
    provenance: dict       # source, bars per symbol, window, age

def propose(*, symbols, frames, equity, positions, strategy, risk,
            selector=None, allocator=None, overlays=(), provenance=None) -> Proposal: ...
def explain(symbol, target, rank, weight, capped, strategy_name) -> str: ...
```

### Call stack
Today refresh: `POST /api/proposal/refresh` -> `JobRegistry.submit("proposal")`
-> `advisor_service.build_inputs()` -> `advisor.propose()` ->
`Storage.record_proposal()` -> page polls `GET /api/proposal`.
Engine: `Engine.rebalance` -> `advisor.propose()` -> `_submit_all(lines)`.

### Test plan
- `test_propose_matches_engine_rebalance_deltas` (lockstep, DryRunBroker).
- `test_propose_marks_non_members_as_sell_with_a_selector_reason`.
- `test_propose_reason_names_the_strategy_signal_and_the_cap`.
- `test_propose_never_calls_a_broker_or_storage` (fakes raise on use).
- `test_latest_proposal_round_trips_through_storage`.
- Web: `test_today_page_renders_empty_state_with_refresh_hint`,
  `test_refresh_job_uses_cached_bars_without_credentials`,
  `test_refresh_job_attaches_a_fetcher_only_with_credentials` (fake fetcher),
  `test_positions_derived_from_the_order_log`.

### Least confident decisions
1. Positions without a broker come from summing signed fills in the order
   log per mode. Partial fills are not modelled by the log, which matches
   the dry-run broker.
2. The reason sentence is assembled from structured parts in `explain`, not
   from per-strategy prose. Strategies gain an optional `describe(bars)`
   hook later if the generic sentence proves too thin.
3. The tab bar after this epic: Today, Run, What-if, More (Dashboard,
   Chart, Arena, Seasons, Consortium).

## E4: Autopilot

### Files
- `tradebot/autopilot.py` (new, core; package `autopilot/` if over 200
  lines). `AutopilotConfig`, `AutopilotState`, `Autopilot` runner.
- `tradebot/storage/autopilot.py` (new mixin). Table `autopilot_state(key,
  value)` and the proposal status transitions reused from
  `storage/proposals.py`.
- `tradebot/engine/core.py`. `rebalance(submit=True)` gains a `submit`
  switch. With `submit=False` the pass records the proposal as pending and
  returns it. `submit_lines(lines)` submits a given list of lines.
- `tradebot/web/services/autopilot_service.py` (new). One `Autopilot`
  instance per web process, created lazily from the server settings, started
  and stopped through the API.
- `tradebot/web/routes/api/autopilot.py` (new). `GET /api/autopilot`, `POST
  /api/autopilot`.
- `tradebot/web/routes/pages.py`. `GET /autopilot`.
- `tradebot/web/templates/pages/autopilot.html` (new),
  `components/pending_trades.html` (new partial).
- `frontend/src/components/autopilot.ts` (new). Mode buttons, approve and
  reject taps, polling.
- `tradebot/cli/run.py`. `tradebot run --autopilot [--mode approve|auto]`
  runs the same runner headless.
- `tests/test_autopilot.py`, `tests/test_web_autopilot.py` (new).

### Types and signatures
```python
Mode = Literal["off", "approve", "auto"]

@dataclass(frozen=True)
class AutopilotState:
    mode: Mode
    running: bool
    started_at: datetime | None
    last_pass_at: datetime | None
    next_pass_at: datetime | None
    last_error: str | None
    pending: int

class Autopilot:
    def __init__(self, engine: Engine, storage: Storage, *, poll_seconds: int,
                 calendar: MarketCalendar, clock: Callable[[], datetime] = utcnow,
                 sleep: Callable[[float], None] = time.sleep) -> None: ...
    def set_mode(self, mode: Mode) -> AutopilotState: ...
    def state(self) -> AutopilotState: ...
    def tick(self) -> AutopilotState: ...          # one pass, used by tests and the loop
    def approve(self, line_ids: list[int]) -> int: ...
    def reject(self, line_ids: list[int]) -> int: ...
    def run_forever(self, max_ticks: int | None = None) -> None: ...
```

### Call stack
Web: `POST /api/autopilot {mode}` -> `autopilot_service.get().set_mode()` ->
thread starts `run_forever` on first non-off mode. Loop: `calendar.is_open(now)`
-> `engine.rebalance(submit=(mode == "auto"))` -> `approve` mode writes
pending lines and notifies -> sleep until next pass or next open.
Approve: `POST /api/autopilot {approve: [ids]}` -> `Autopilot.approve` ->
`engine.submit_lines(lines)` -> status `submitted`.

### Test plan
- `test_tick_in_auto_mode_submits_every_line`.
- `test_tick_in_approve_mode_stores_pending_and_submits_nothing`.
- `test_approve_submits_only_the_chosen_lines_and_marks_them`.
- `test_reject_marks_lines_and_submits_nothing`.
- `test_loop_sleeps_through_a_closed_market_with_an_injected_clock`.
- `test_daily_loss_halt_sets_mode_off_and_records_the_error`.
- `test_state_round_trips_through_storage_across_restart`.
- Web: `test_autopilot_page_shows_mode_and_pending`,
  `test_mode_switch_through_the_api`, `test_approve_through_the_api`.
- CLI: `test_run_autopilot_headless_replay_ticks`.

### Least confident decisions
1. One runner thread inside the web process. A separate daemon is not
   needed for a single user. The CLI path exists for headless use.
2. A stale pending proposal (older than one poll interval) is replaced by
   the next pass, not executed. Prices moved.
3. Live mode keeps the existing gate and is not reachable from the web UI.
   The mode switch changes approve/auto only. Paper versus live is the
   config file plus the env latch, as before.
